# 运行位置与脚本依赖

规则和操作方法由本 skill 及其 references 维护。执行时从当前工作区、用户已提供的配置和现有 skill 安装解析实际位置；只在无法确定操作范围或缺少必要决定时询问用户。

## 执行时解析的内容

| 内容 | 如何使用 |
| --- | --- |
| DeepCoffee 工作区 | 核对本次选定的仓库及其当前说明，在该工作区运行相关命令 |
| 前后端目录 | 沿用项目已有的 frontend、deepcoffee-api 目录或用户指定的实际位置 |
| 后端解释器 | 使用该后端已有的虚拟环境和项目依赖，按原流程从后端目录运行维护工具 |
| 部署脚本 | 将已核实的 deploy_backend.sh 实际位置用于 `DEEPCOFFEE_DEPLOY_SCRIPT` |
| 维护脚本 | 将已核实的 storage_cleanup.py 实际位置用于 `DEEPCOFFEE_MAINTENANCE_SCRIPT` |
| 账号脚本 | 将已核实的 reset_account.py 实际位置用于 `DEEPCOFFEE_RESET_SCRIPT` |
| 生产目标与环境 | 读取用户自己的现有运行配置；服务目标、项目标识、密钥和环境值保持在该配置中 |

这些变量是命令示例中的运行绑定。使用前确认对应文件实际存在、参数与本次操作一致；任务中已确认的路径继续有效。以当前用户要求、适用规则和实际工具权限决定可执行范围。

## 当前脚本状态

本轮已只读确认 deploy_backend.sh、storage_cleanup.py、reset_account.py 均存在于现有本地 deepcoffee-dev 的运行目录。部署脚本包含 Cloud Run 发布命令；两个 Python 脚本依赖 DeepCoffee 后端包、环境和虚拟环境，维护脚本还触发存储及支付维护方法。

这三个脚本继续作为本 skill 的现有运行依赖，不迁入项目仓库。本轮公开整理恢复了操作规则和命令，尚未将三个脚本实现打包到本仓库，也未修改旧安装或项目配置。整体安装整理时再处理脚本打包、运行绑定和旧位置接入。

如果脚本缺失，报告缺失的具体文件及受影响的操作。维护前置检查失败按 [operating-rules.md](operating-rules.md) 继续主任务；主任务自身需要的脚本缺失时，应准确说明尚未完成的操作。
