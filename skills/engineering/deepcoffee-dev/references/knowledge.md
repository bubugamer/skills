# 知识库审阅与文章纳入

## 能力：wiki-review（知识库审阅与拆分建议）

用于审阅 DeepCoffee 知识库内容、外部文章或一组链接，判断哪些内容值得纳入知识库、哪些应该作为模型注释、哪些用户正文需要清理。

### 触发

- 用户说「wiki-review」「检查知识库」「看看这些文章是否值得纳入」「对照知识库调研」「知识库文章怎么整理」。
- 用户指出知识库正文里出现了内部指令、模型提示、品牌宣传、来源残留或不适合给用户看的内容。

### 流程

1. 先定位现有内容：
   ```bash
   rg "<关键词>" knowledge -g "*.md"
   rg --files knowledge | sort
   ```
   优先更新已有文章；只有没有合适承载页时才建议新增。

2. 把结论分成三类：
   - 用户可读正文：放在普通 `knowledge/**/*.md`，面向咖啡知识阅读。
   - 模型注释：放在同目录 `原文件名_model_notes.md`，只处理识别、归一化、保存、检索、回答边界。
   - 不纳入：重复、品牌宣传、营销口号、只对单一商家有效且无法泛化的内容。

3. 审阅时必须列清单，不只给数字：
   - 建议新增或修改的用户正文文件。
   - 建议新增的 `*_model_notes.md` 文件。
   - 需要从用户正文清理的内部指令、品牌标识、宣传语或来源残留。
   - 暂不处理的内容和原因。

4. 用户正文和模型注释拆分规则：
   - 用户正文写给用户阅读，不出现「模型应该」「系统应该」「DeepCoffee 应保存」「归一化时」等内部实现口吻。
   - 模型注释写给模型使用，可以说明同义词、不要误归并、字段保存边界、器具类别判断、处理法组合边界。
   - 纯别名、无明显解析风险的实体页，不批量新建模型注释，避免制造低价值文件。

5. 必要检查：
   ```bash
   rg "DeepCoffee 应|模型应该|系统应该|字段应保存|归一化时" knowledge -g "*.md" -g "!*_model_notes.md"
   ```
   如果发现用户正文里仍有内部口吻，先提出或直接修正。

## 能力：wiki-add（文章重写并纳入知识库）

用于把外部文章、公众号文章、网页内容或用户提供的资料重写进 DeepCoffee 知识库。添加时要同时考虑用户可读文章和模型注释。

### 触发

- 用户说「wiki-add」「加入知识库」「纳入知识库」「把这篇文章整理进知识库」「注明来源加入」「隐藏来源加入」。

### 两种加入模式

- 注明来源：在 frontmatter 的 `sources` 和必要的「来源」段记录来源。正文仍必须是中性改写，不保留宣传语。
- 隐藏来源：不在用户正文和 frontmatter 展示来源。仍要重新组织语言，不能直接复制外部文章。

如果用户没有说明模式，先按上下文判断；会影响是否展示来源时再问一句。

### 内容处理原则

- 不直接搬运原文；用 DeepCoffee 的中性知识库口吻重写。
- 去掉品牌标识、商家自称、销售话术、活动引导、关注/购买/扫码/门店宣传、夸张宣传语。
- 保留可泛化的咖啡知识：概念、机制、判断边界、冲煮方法、豆袋字段、品种/处理法/器具识别规则。
- 如果文章来自某个品牌或商家，除非主题就是该品牌实体页，否则正文不要让用户读起来像品牌介绍。
- 有冲突或不确定的信息，不强行定论；标明“可能”“常见”“需结合豆袋原文”。

### 写入规则

1. 先查找已有承载页，优先更新：
   ```bash
   rg "<主题关键词>" knowledge -g "*.md"
   ```

2. 新增用户文章时，遵循现有 frontmatter 风格，至少包含标题、分类、状态、日期、可见性和索引设置。公开文章需要考虑是否加入 `knowledge/index.md` 和 `mkdocs.yml`。

3. 同时判断是否需要模型注释：
   - 涉及品种命名争议、同义词、别名、市场俗称、不可自动归并时，考虑新增同目录 `*_model_notes.md`。
   - 涉及处理法组合、大类标签、非标准命名、添加物或发酵边界时，考虑新增模型注释。
   - 涉及器具、滤材、磨豆机型号、尺寸、刻度、类别边界时，考虑新增模型注释。
   - 只有普通背景知识或用户也该看到的解释时，不要新建模型注释。

4. 模型注释文件必须使用同目录后缀方案：
   ```markdown
   ---
   visibility: model
   audience: model
   target: 原文件名.md
   indexable: false
   ---
   ```
   模型注释不加入 `mkdocs.yml` 导航，不加入 `knowledge/index.md`，不作为用户来源展示。

5. 完成后必须列出：
   - 新增或修改的用户正文文件。
   - 新增或修改的模型注释文件。
   - 清理掉的品牌标识、宣传语、内部指令或来源残留。
   - 使用的是「注明来源」还是「隐藏来源」模式。

### 验证

- 内容隔离：
  ```bash
  rg "DeepCoffee 应|模型应该|系统应该|字段应保存|归一化时" knowledge -g "*.md" -g "!*_model_notes.md"
  ```
- 构建检查：
  ```bash
  .venv/bin/mkdocs build
  find site -name "*_model_notes*" -print
  ```
- 如果改了知识库服务或模型注释机制，再做 API / 服务检查，确认 `*_model_notes.md` 不出现在文章列表、详情、select-files、sources 或 selected_files 中，但选中原文时能附加进模型上下文。
