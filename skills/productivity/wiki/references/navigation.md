# 导航与规模维护

新增、改名、合并、拆分或归档页面，以及调整主题结构时读本篇。先识别项目已有导航模型，保持有用结构。

## 入口的分工

采用 MkDocs 和主题页的项目可以沿用原有三种入口：

| 入口 | 职责 | 何时更新 |
| --- | --- | --- |
| 首页 | 展示主题分类与主题页，提供简短说明。 | 主题分类或主题入口变化。 |
| 主题页 | 组织下属页面，说明各页的位置及彼此关系。 | 所属页面、链接或主题认识变化。 |
| MkDocs `nav` | 表达项目要求的完整站点页面树。 | 应列入站点导航的页面新增、改名、移动或移出。 |

首页不必列出每个子页面。采用完整 `nav` 的项目应按项目规则纳入内容页及应展示的维护页；归档、私有内容和附件的处理沿用项目规则。不把所有 `.md` 文件一律塞入首页。

纯 Markdown 知识库可以只有首页和主题页，不为使用 skill 强加 MkDocs、指定索引名或新一套 `_index-*` 文件。

## 一次页面变化如何同步

1. 找到页面当前归属、相关主题入口、站点配置及所有入链。检查普通 Markdown 链接，也检查项目实际支持的双中括号、别名与章节链接。
2. 保留已有内容与有意义的关系。合并或拆分先列出旧页到新页的对应关系；已批准范围内执行，不把未决定的提案当作既定结构。
3. 调整页面与主题页。改名、移动时更新相对路径、入链、必要的附件链接及已变化的章节锚点；检查出链在新位置仍能解析。
4. 更新受影响的首页与站点导航。仅内容修订通常不需要改变首页或站点页面树。
5. 检查目标存在、导航覆盖和重复条目；使用构建检查时先确认项目依赖和构建动作。记录一次合并的知识变更日志。

本地文件存在与网页可跳转是不同检查。链接到站点目录外的来源笔记可以作为本地证据，但不能据此声称公开网页也能访问；按项目的来源呈现方式处理。

配套工具提供只读导航与链接检查，参数见 [健康检查](health-check.md)。它不生成或覆盖首页，也不改写站点配置。

## 可发现性与交叉链接

有清晰主题入口的页面不算无法发现，但仍可能缺少知识关联。分别报告「从任何入口都找不到」和「只有目录入口、缺少相关页联系」。添加链接应说明真实关系，不为了消除孤立统计而互相乱链。

## 随规模调整

当入口难浏览、主题混杂或搜索命中不准时，再调整结构：

- 先改标题、一句话概述与主题归属，再补有意义的交叉链接。
- 主题过宽时按实际问题拆分；内容少且关系紧密时可合并，不按页数机械决定。
- 需要理解跨主题关系时，增加关系说明或主题地图，而非再复制一份全部页面清单。
- 不活跃但有历史价值的内容按项目归档方式保留，并维护可发现的历史入口和引用。
- 现有导航与文本检索不足时，再评估轻量搜索；已有活动日志继续使用，不因规模增加另建重复变更日志。

结构调整应可回溯，Markdown 文件及其基本关系在没有站点服务时也应便于阅读。旧版的 80／200 页、30／3 页阈值是经验提示，不作为自动重组条件。
