# 本地站点操作

用户要求启动、打开或停止本地 Wiki 时读本篇。具体命令、路径、依赖与地址来自知识库项目，见 [工作区约定](workspace-profile.md)。

## 打开或启动

1. 查看项目已有站点说明和启动脚本，确认运行目录、启动命令、依赖、监听地址及检查就绪的方法。只有 Markdown 文件、没有站点配置时，说明现状并展示可直接阅读的入口；搭建新站点另按用户要求处理。
2. 检查项目站点是否已运行。确认是目标知识库的服务后可直接复用；同一端口上的其他服务不等于目标站点就绪，不结束未知进程来腾端口。
3. 需要启动时，使用已确认的项目命令。缺少依赖时报告具体缺项并按已有环境管理约定处理，不默认为全局安装或创建一套新运行环境。
4. 保留本次启动的进程或服务标识、实际地址和输出位置。观察实际启动结果；通过项目适用的 HTTP 响应、启动日志或页面内容确认就绪。页面需登录时按预期响应判断，不把任意 200 响应视为正确站点。
5. 就绪后通过当前可用的浏览器能力打开实际地址，并向用户提供链接。启动失败时查看错误；仅调整本次授权范围内的配置。等待超过启动日志或项目约定允许的时间仍未就绪时，报告实际状态，不宣称已启动。

不固定等待三秒，不把特定端口当作可用保证。项目命令可能已经管理后台进程，不再叠加一套未经确认的启动方式。

## 停止

优先使用本次启动记录或项目明确管理的停止方式。关闭本次启动的服务后，验证相应进程或服务已退出；需要时确认地址不再提供该服务。

对于启动前已存在的服务，先确认用户要求停止的正是它及项目如何管理它。无法确认归属时说明情况，不用全局进程名匹配批量结束。单次请求失败不一定代表服务已经退出。

## 本地与公开站点

沿用项目实际的可见性规则。本地是否包含全部页面、公开构建如何过滤，都由项目实现决定；不要从 `visibility` 属性或一次本地打开推断发布行为。

本地启动不包含发布动作。只有用户提出相应需求时，再根据项目的发布方式与已有授权执行和验证。
