# Workflow

## 1. 普通网页

1. 先尝试直接读取正文。
2. 如果直接读取已经足够，就不要上浏览器。
3. 如果只拿到壳页面，再转浏览器。

## 2. 短链接

1. 先解析短链接跳转。
2. 记录原始链接和最终链接。
3. 对最终链接再做正文判断。

## 3. JavaScript 渲染页面

1. 用 `agent-browser` 或 `playwright` 打开页面。
2. 等待网络稳定。
3. 必要时点击“展开”“继续阅读”“显示更多”。
4. 必要时滚动页面，直到正文完整出现。
5. 提取主内容，而不是整个页面外壳。

## 4. 登录后页面

1. 用带界面的浏览器打开页面。
2. 如果需要，导航到登录页。
3. 让用户在浏览器里手动完成登录或 2FA。
4. 登录成功后保存本地状态文件。
5. 再回到目标页面抓正文。

## 5. X / 社交平台内容

1. 先判断输入是短帖、线程、站内长文还是跳转链接。
2. 先检查当前渲染页面里是否已经出现可读正文。
3. 如果贴文本身已经展开了长文或主要内容，优先提取当前页面正文，不要因为看见 `t.co` 就立刻跳走。
4. 如果页面正文仍然只有短链接、预览或壳内容，再去解开短链接。
5. 如果首屏是瞬时错误、空白容器或正文节点还没出现，先等待、重新快照，必要时重载一次，再判断是否失败。
6. 如果最终落到站内长文页，确认公开未登录是否可读。
7. 只要正文不可见，就停止，不生成伪抓取结果。

## 6. 抓取成功后

输出文件中至少保留：

- 原始链接
- 最终链接
- 获取日期
- 获取方式
- 正文

如果布局重要，可额外保存截图。
