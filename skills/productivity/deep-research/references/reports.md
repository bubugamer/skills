# Requested standalone reports

Resolve the audience, decision, scope, destination, and requested formats from the user's instructions. Create only the requested outputs. Use a user-configured destination when available; ask if a required location is still missing.

A useful structure is:

1. Question and conclusion.
2. Scope, relevant dates, and material assumptions.
3. Findings with nearby source citations.
4. Alternatives, counterevidence, and uncertainties.
5. Implications or recommendations when requested.
6. Sources and a brief account of the verification performed.

Adapt this structure to the task. No universal word count, source count, executive-summary length, or house style is required. Keep facts and your synthesis distinguishable throughout.

Markdown may be sufficient. If HTML or PDF is requested, use the current environment's document tools to generate it from the agreed content. Inspect rendered output for clipping, missing content, table and citation readability, and links or references as appropriate. A successful conversion alone is not a visual check. Do not automatically open or generate other formats.

Validate separately:

- **Content:** key claims actually follow from the inspected source passages.
- **Attribution:** references point to the intended source and locators are usable.
- **Completeness:** the requested questions are answered, with gaps stated.
- **Presentation:** requested files exist and their layout has been inspected where relevant.

Link accessibility and record-format checks are useful partial checks. They do not establish factual support. Repair issues within the authorized scope; when a necessary source or tool is unavailable, preserve the work and explain the precise delivery limit.

Return the actual file locations and a short account of what was checked. Include evidence records only when they are part of the agreed deliverable.
