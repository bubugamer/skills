# read

围绕正在阅读的材料帮助用户理解、讨论和记录，同时处理材料的初步筛选、分类与阅读队列。

## 阅读与共读

1. 沿用已经读过的材料、用户背景和当前问题。区分阅读价值判断、摘要、翻译、段落问答、背景解释、出处追溯、材料筛选分类与笔记，不让固定输出格式替代本次问题。
2. 获取足以支撑回答的正文。普通网页直接读；遇到渲染、跳转或登录障碍时参考 site-unlocker；PDF、文档、音频使用当前可用的相应工具。
3. 用户给出的完整段落可以支持该段的解释，无需先取得全文。只有标题、预览或登录墙时，不声称读过文章，也不编造全文摘要或阅读价值；明确本次实际覆盖的材料。
4. 先回答当前问题，再补足必要背景。连续追问时沿用上下文，按需要解释公式、代码、术语、论证和具体例子；区分作者观点、补充知识与尚未核实的推断。翻译按用户要求的范围和方式进行，不用摘要代替全文翻译。阅读价值判断可用「现在读 / 先收藏 / 可跳过」并给出理由；出处核实按需读取 [出处判断](references/source-evaluation.md)。
5. 用户要求「保存 / 收藏 / 记下来 / 沉淀」时，先确定目标知识库，按 references/routing-rules.md 选择位置，再按 references/note-templates.md 保存。用户的持续授权适用于已指定工作区。普通总结、翻译和讨论本身不启动写入。
6. 阅读笔记记录材料主线、关键概念、已厘清的解释、必要的正确推导或例子，以及仍待解决的问题；不把来回问答写成流水账。多轮共读按收束后的结论单元记录，保留旧结论和来源，报告实际写入的位置。

## 工作区与写入边界

`<knowledge-root>` 是用户指定的知识库根目录。优先读当前项目的 docs/agents/skill-workspace.md；没有配置时，只在真正需要保存而目标不明时询问。不要猜测个人目录，不把占位符当成真实路径。

- 只判断值不值得读：会话回答；若同时要求收藏，更新阅读队列，不顺带创建伴随笔记。
- 已进入摘要或共读：会话回答；若同时要求保存，记录已收束的结论。
- 尚未获取正文：不创建空笔记；用户明确要求先记入口时，可保存一个标明未读取的链接。
- 材料分类与筛选：按用户目标整理主题、标签、来源和阅读状态；不顺带重建整个知识库或工作区。
- 学习项目、调研项目或长期主题页：按明确任务处理，日常阅读不自动扩展到这些流程。
- 已有目录和模板继续适用；[保存链条](references/routing-rules.md) 中的历史目录模型留待统一整理，未被当前工作区选定的路径不作为默认要求。

## 完成条件

实际读到的内容能支持结论；引用能回到原始来源；没有把推断写成事实；写入范围与本次要求一致。
