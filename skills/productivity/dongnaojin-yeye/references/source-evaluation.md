# Source Evaluation

这个文件定义出处追溯时的处理方法。目标不是“看起来像找到了”，而是把可验证和不可验证部分清楚拆开。

## Workflow

1. 提取线索
   - 关键短语
   - 人名、机构名、产品名
   - 文章标题、播客标题、论文名
   - 明显像引用的话
2. 先查本地知识库
   - 优先在 `<knowledge-root>` 里搜索精确短语和关键实体
   - 找已有文章、转写、摘要、伴随笔记
3. 再查公开来源
   - 对外部公开内容，用精确短语、标题、作者名、实体组合搜索
   - 优先原始发布源、官方站点、论文页面、作者主页
4. 判断来源链
   - 原始来源
   - 二手转述
   - 三手摘要或拼接内容
5. 输出可信度
   - 已验证事实
   - 高概率推断
   - 无法验证部分

## What Counts As Verified

只有满足下面任一条件，才算“已验证事实”：

- 找到原始页面、原始文章、原始论文或官方发布源
- 本地知识库中已有明确的原文链接、作者、标题且能和当前内容对应
- 多个独立来源能相互印证同一个事实点

## What Counts As Probable

以下情况只能归为“高概率推断”：

- 文本高度相似，但没有看到原始发布源
- 只找到二手转述或摘要稿
- 线索能指向某个作者或某篇文章，但关键字段不完整

## What Counts As Unverified

以下情况必须归为“无法验证部分”：

- 只找到相似说法，找不到可靠源头
- 内容可能是多个来源拼接
- 只看到 AI 改写稿或转录稿，无法反推原始出处

## Output Rules

- 不要把推断写成事实。
- 不要为了给出答案而补造作者、标题、来源。
- 如果只能定位到“最接近的来源链”，明确告诉用户这是“最接近”，不是已确认原始出处。
- 如果本地知识库中已经有来源信息，优先复用，不必重复发明一套说法。
