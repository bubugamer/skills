# 写给人的使用说明

每个 catalog 条目在 docs/对应分类/有使用页：目的、何时选它、输入或依赖、一句用法、完成条件、邻近能力、已知限制。

SKILL.md 给 AI 操作，docs 给用户选择；两者不重复整套步骤。调用策略只写在 .agents/invocation.md；安装步骤集中在 docs/installation.md。

README 和各技能使用页提供五列场景表：具体场景、用户可以怎样提出要求、使用哪个 skill、AI 如何协助、最终产出。内容以 catalog.json 的 usage_scenarios 为单一来源，由 sync_catalog.py 生成。每个场景应是可直接理解的实际用法，保留来源、登录、保存或执行范围等会影响结果的条件。

场景表先收用户已确认保留的技能，以 review.admission_status 的 user-approved 标记并关联确认依据；已有源码或位于默认发布清单不代替用户确认。审阅通过并确认留在个人集合时，补齐至少一个代表场景，生成 README 和对应使用页。用户已授权 OpenAI 官方项目按来源批量跳过，无需逐项内容确认；仅保留处理结论，移出 catalog、使用页和生成推荐，不计入已保留场景数量。待审项与候选留在审查文档，brief 等迁出项单独记录，不混入场景表。

术语只在 GLOSSARY.md 定义；事实来源写 ORIGIN.json；改动写 CHANGELOG；长期重要权衡写 .agents/adr；本轮审查判断写 docs/audit。场景用例和实际执行记录分开。

## 审查收尾

用户每次确认某项技能审阅通过后，都更新同一份 [分批审查清单](../docs/audit/review-checklist.md)，保留最终决定、证据、当前用途目录和待审状态。

第一轮只审阅原有 32 项；Matt 未引入技能是第二批扩展候选，侧重是否值得纳入；ask-skills 等本轮新增入口单列为体系维护。teach 已确认引入，wait-what 属于原有集合，不重复计数。

清单首页列出已审阅保留的技能及用途目录，迁出项与按用户规则跳过的官方项目另列；批量跳过计入已确认处理，不冒称逐项内容审阅通过。取消 in-progress 目录；已知问题和验证范围在使用页与记录中维护。源码、目录、安装或发布清单存在不等于用户已审阅通过。

每次通过后的回复列出已审阅保留的技能及目录、其他已确认处理项和第一轮全部待审名称；Matt 第二批仅列概览和链接，用户要求时再展开。只给第一轮总数或链接不代替名称清单。原有、Matt 候选与体系新增项不合并成当前待审总数；更名或已计数技能完成整改不重复计数。

集合内技能标识放 catalog 的 dependencies；不在个人集合的外部运行工具要求写入 inputs，不为表达运行依赖而重新收录已排除的官方技能。移除条目时仍保留真实工具需求与已有已知问题。
