# Codex 调用策略

当前已接入 22 项仓库技能；2026-10-29 追加用户明确批准的 grilling，保持上游正常自动选择，也可用 $bubugamer-skills:grilling 手动指定。此前 2026-10-21 用户授权的本机统一接入已完成：21 个已确认技能链接到仓库源码，两项外部能力沿用原安装。旧入口与配置保留恢复资料；普通安装器仍只预览并报告新冲突，不自动覆盖。见 [当前范围](../SCOPE.md) 与 [安装说明](../docs/installation.md)。下列较早的更名和暂缓记录保留为历史。

每个技能保持 name 与 description。agents/openai.yaml 控制手动或自动选择，按 catalog.json 的 manual 属性生成。目录分类与调用方式分别维护；移动目录时保留当前调用设置。

按当前工具的技能机制加载入口，不假设存在 Skill 工具。路由仅推荐。缺少外部能力时说明依赖，不自动安装多个工具。用户已明确选择任务时，不必先经过路由。

安装只选择一个入口：正式 plugin 或受控本地链接；同名技能与 remind 的 TangMonk/tang-monk 旧名视为冲突。当前 legacy .codex 与 .agents 安装仍可能共存，按实际路径核查。

read 的旧名 dongnaojin-yeye 也属于安装冲突；用户已明确授权的更名按具体迁移方案备份后执行，不让两个名称同时被发现。

read 与 teach 是独立入口。当前上下文明确选择 teach 后，该学习任务的阅读、翻译、问答与记录由 teach 负责；其他阅读默认 read。深度、追问次数或换教材不自行改变入口。辅助角色与手动／自动策略分开维护。

para 的旧名 konmari 同样属于安装冲突。用户明确授权本次更名后，保留完整备份再迁移；旧名与新名不同时作为可发现入口。

wiki 的旧名 llm-wiki 同样属于安装冲突。用户已确认更名与本轮整改，备份后迁移到正式 wiki；保持原手动调用方式。基于知识材料的自测使用 teach，wiki 维护长期知识内容与导航。

writing-styles 的旧名 writing-master 同样属于安装冲突。用户已确认多文风整改与更名，完整备份后迁移，保持原有自动选择设置；新旧名称不同时作为可发现入口。

skill-creator 的创建、维护与评测共用一个入口，评测按任务需要选择。仓库版、系统入口与本机旧版本存在同名可能；最终统一迁移时核对真实发现来源，选定一个个人使用入口，普通安装遇到已有同名目录仍报告冲突，不替换用户原安装。该迁移已于 2026-10-21 获授权完成，旧版保留归档，系统同名入口通过用户配置关闭，仓库版启用。

2026-10-21 Matt 四项写作技能获准纳入 productivity：writing-fragments、writing-shape、writing-beats 保持上游手动调用设置；writing-for-agents 保持正常自动选择。入口保留英文说明并追加中文回复要求；旧宿主调用字段由 agents/openai.yaml 承接，配套 mechanics 文档按当前 Codex 规则维护。用户按本次写作需要选择阶段；与 writing-styles 的用途组合不代表自动串联全部技能。

本次实际发现名称带 bubugamer-skills: 前缀；明确选择时以当前技能选择器的完整名称为准，如 $bubugamer-skills:ask-skills。用户配置变更后重启 Codex 刷新，实际发现已通过独立本地服务读取验证。
