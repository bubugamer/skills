日期：2026-10-20。状态：用户已确认按建议整改，仓库改造与本地配方验证已完成，审阅通过。第一轮现已处理 12 项、待审 20 项；本机安装留待全部审阅完成后统一处理。下文先保留整改前的审阅依据，最终落地与验证见文末。

## 创建背景与实际使用

核实 2026-05-20 的原始用户消息：用户先考虑类似 Downie 的应用，随后明确表示暂时不做应用，直接基于 yt-dlp 建立 skill；并要求按 skill-creator 流程制作。同一会话中由 Codex 创建 yt-dlp-download。

当时用户接受的方案包括：明确要求下载时才调用 CLI，默认存 Downloads/sourcesget，需要登录的网站默认使用 Chrome 登录状态，合集先列清单再按明确范围下载。由此可见，目录和浏览器有历史偏好依据，不能因为它们具体就认定应全部删除。

2026-05-23，用户明确说「接下来那就试试这个 skill」，要求下载小宇宙链接的音频，随后讨论实际保存路径中出现 audio/generic。当前版本按媒体类型分组、不用 extractor 建目录，与这段使用背景相符。本轮核实了创建需求及一次显式试用与保存位置讨论，未统计全量使用次数，也没有重新读取当时的下载文件。

## 来源与当前定位

底层下载能力来自 [yt-dlp](https://github.com/yt-dlp/yt-dlp)，媒体合并及转码使用 ffmpeg。本地 skill 由用户提出、Codex 整理下载工作流，并非 Matt 的技能。它直接调用已有 CLI，符合用户当时不再额外封装 Python CLI 的选择。

当前有四类任务：下载视频、提取音频、仅查看媒体信息、按范围下载合集。它不负责一般文章阅读、音频转写、磁力或 BT 下载。

仓库只有 141 行 SKILL.md 和展示、来源、场景元数据，没有自有下载脚本或配套参考文件。长处是直接复用成熟工具；可改善之处是入口中重复了较多完整命令、路径与参数。

## 已有设计中值得保留的内容

- 明确下载或查看意图后执行；用户只给链接时先依据上下文确定意图。
- 默认保存 Downloads/sourcesget，视频和音频分开；用户指定目录优先。
- 文件名包含标题与媒体 ID，配合不覆盖参数；下载记录用于避免重复。
- 合集先检查并尊重已明确选择的范围，用户已要求全部时不再重复询问。
- 输出实际成功、跳过或失败结果，并给出可用文件位置。
- 保持英文技能指令，使用当前对话需要的回复语言；不为了中文回复重写成中文版。

## 实际验证

使用现有 yt-dlp 2026.06.09 与 ffmpeg 8.1.2。生成一秒黑色视频和合成音频，在临时目录启动仅绑定 127.0.0.1 的 HTTP 服务，使用真实 CLI 执行。所有媒体均为本轮生成；没有下载外部网站媒体，没有读取 Chrome 或其他浏览器登录状态。测试明确忽略用户全局配置并关闭缓存与 cookies。

| 实际操作 | 结果 | 能说明什么 |
| --- | --- | --- |
| 只查看单个媒体的 JSON 信息 | 成功，未执行媒体下载 | 仅查看与下载可以区分 |
| 下载一个视频并提取 M4A | 均成功；ffprobe 确认视频有视频／音频流，M4A 为音频流 | 单条视频和音频主路径可用 |
| 提取音频前后比较已保存视频指纹 | 视频保持不变 | 现有媒体类型分目录有实际作用 |
| 同一链接先提取 M4A，再用相同音频下载记录请求 MP3 | 第二次退出成功但被记录跳过，没有生成 MP3 | 不能把「跳过已下载」等同于完成新的格式请求 |
| 查看本地双视频页面并用 --no-playlist 下载 | 识别出两项；仍下载两项 | 该参数不保证纯合集只下载一个 |
| 明确 --playlist-items 1 | 只生成一个媒体文件 | 按用户选择范围执行的做法可用 |

官方说明中，--no-playlist 针对同时指向单条视频与播放列表的 URL；并非任意合集的硬性数量限制。现有合集章节要求预先查看，这个意图正确，但不应在普通下载命令旁将该参数描述为完整的防批量保护。

本轮没有验证外部网站登录、反爬行为、线上合集或全部支持站点；这些本地测试不能证明真实网站始终可下载。

| 内容 | 取舍 | 原因 | 建议处理 | 使用场景 |

| 名称与下载定位 | 建议保留 | 有明确创建需求和实际试用 | 保留 yt-dlp-download，归 misc | 保存用户指定的视频和音频 |
| 直接调用 yt-dlp | 保留 | 成熟工具已承担下载能力，符合用户原始决定 | 不另外建立一套下载程序 | 普通视频、音频、媒体信息查看 |
| 英文入口与完整命令示例 | 入口精简，示例外置 | 当前重复路径与参数较多 | 核心选择与结果要求留入口；常用命令按需查参考 | AI 快速选择正确模式 |
| 目录与命名 | 保留已有偏好 | Downloads/sourcesget 与按媒体类型分组有历史依据，路径已用 HOME 表达 | 用户目录优先，默认值集中维护，保留媒体 ID 和不覆盖行为 | 连续收集视频与音频 |

| 依赖与完成核对 | 保留，按操作需要使用 | 下载、合并、转码和仅查看需要的能力不同 | 先核对相应工具，完成后检查文件及媒体格式 | 仅查看、音轨提取、视频合并 |
| 场景用例 | 后续补齐 | 目前只有一条笼统场景 | 加入仅查看、纯合集、选择范围、换格式和重复下载 | 后续维护与模型行为检查 |

## 本轮结论

建议独立保留，以简洁入口调用成熟 CLI；改善合集识别和按目标格式处理下载记录，并按原接受方案限定浏览器登录状态的使用时机。下载目录偏好与音视频分组继续保留。

这些是供用户审阅的具体取舍，本轮没有改写入口、增添脚本、修改安装或把该项标记通过。来源记录已按实际创建证据补齐，实际检查记录见 [verification.md](verification.md)。
