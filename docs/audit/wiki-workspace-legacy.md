# llm-wiki 原工作区设置存档

日期：2026-10-16。为后续统一整理个人目录模型，单独保留 [原 SKILL.md](llm-wiki-original/SKILL.md) 的项目绑定内容。以下是旧约定的记录，不是新版 wiki 的全局默认值。本次不修改真实知识库或创建新配置文件。

## 原路径与角色

以下均相对用户自己的知识资料根，不含个人绝对路径。

```text
<knowledge-root>/
├── 02-Areas/
│   └── _wiki/                 知识库项目根
│       ├── docs/             Markdown 页面目录、MkDocs docs_dir
│       │   ├── index.md      精简首页，仅主题分类与 topic 入口
│       │   └── log.md        追加式活动日志
│       ├── mkdocs.yml        完整站点 nav
│       ├── serve.sh          旧说明中的本地启动入口
│       └── .venv/            旧说明中的运行环境位置
└── 03-Resources/
    └── articles/
        └── 共读笔记/          只读来源笔记
```

知识页编入时读取共读笔记，不改原材料。页面新增、改名或归属变化需同步相应 topic 与站点导航；只有主题入口变化才更新精简首页。

## 旧页面与发布约定

- 内容页属性：title、created、last_updated、status、tags、sources、visibility；状态值是草稿／已看过／已确认。
- 导航型主题页以 type: topic 区分，旧示例省略了 visibility，与旧正文要求不一致。
- 旧正文将新页 visibility 默认为 public，并宣称 private 会在公开构建自动过滤。新版不把这一声明视为通用能力；最终沿用哪些默认值，需读取知识库实际配置。
- 旧导航模型使用精简 index.md、topic 页、完整 mkdocs.yml nav；旧参考文档却仍提 _wiki-index.md 与 _index-*，后续配置整理需要统一口径，不能让两套索引同时支配页面。

## 旧站点设置

- 启动入口：项目根的 serve.sh。
- 本地地址：旧说明为 http://127.0.0.1:8732。
- 环境：旧说明为项目根的 .venv，由启动脚本激活。
- 本地内容：旧说明称包含全部页面，包括 private；应以项目实际启动与过滤流程核对。
- 停止：依据本次启动进程的记录处理，不能按通用进程名批量结束。

固定等待三秒和「端口不常用所以适合长期后台运行」不作为新约定保留。新方法是核对实际服务与就绪结果。

## 后续配置整理时确定

1. 以上路径与导航分工哪些继续使用，哪些已由当前项目文件替代。

3. 启动脚本、地址、依赖、进程管理与就绪判断。
4. 将确认后的有效设置放入知识库已有说明或用户选定的配置文件；文件名与其他个人工作区约定最后统一整理。
