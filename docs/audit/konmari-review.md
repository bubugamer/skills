## 命名建议

用户提出将 tang-monk 改成表达用途的名称，建议采用 remind，与 read、teach 的动作命名一致。tang-monk 已符合小写与连字符的格式要求；改名的价值是让用途更直接。当前仓库及两个本地技能目录未发现 remind 同名入口。这是 PARA 初审阶段的名称建议，当时尚未执行；2026-10-15 用户随后明确要求，已补全更名 remind，见 [提醒技能更名记录](tang-monk-review.md)。

## 现有用途

konmari 的当前说明包括目录盘点、文件统计、同名与同内容查重、可视化审阅、分类建议、整理计划，以及按计划移动、隔离或打包文件。用户在本轮澄清主要需求是「PARA 专用工具：重点按 PARA 重建目录」。此前通用文件整理助手的建议据此撤回，盘点、查重与审阅作为 PARA 重建的内部步骤，而不是并列的核心定位。

核心产出应为用户选定目录的 PARA 重建方案，以及按已明确要求和授权完成的重建结果。Projects 对应有目标与结束条件的当前项目；Areas 对应持续责任；Resources 对应参考与复用材料；Archives 对应结束或退出当前使用的内容。具体个人目录名称与编号由工作区配置提供。

既有讨论中，用户曾同时选用 konmari 与 llm-wiki 评估笔记属性。该例只证明它曾参与资料管理讨论，不据此推断完整使用次数或最初创建目的；知识内容与导航的维护范围仍需同文件整理分清。

## 初步建议

- 以 PARA 重建为主流程：理解现状和用户目标，盘点与查重，识别已有分类及目录整体性，区分四类，生成并检查重建方案，再按授权执行并核对恢复记录。
- 保留批量盘点、精确查重、现有分类识别、操作记录及恢复方案；内部工作目录可作为重建过程的持久依据，继续排除在用户内容之外。
- SKILL.md 保留 PARA 的核心分类原则、必要决策点和完成条件；具体算法、命令与目录映射在配套参考文件和工作区配置中维护。
- 有意义的目录可以作为整体保留；混合多个用途的目录才按需要拆分。已知的个人编号不作为通用 PARA 分类依据。
- 可先交付方案并停在相应阶段，日常查目录和打包用途不扩展本技能的核心定位。
- 执行前核对本次选定范围和目标冲突，按用户已明确的要求与授权执行；需要额外决定时给出可审阅方案。
