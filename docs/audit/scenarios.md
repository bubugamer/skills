# 用户用例与完成标准

| 触发 | 用户操作 | 预期行为 | 歧义或失败处理 |
| --- | --- | --- | --- |
| 不知道选择什么能力 | 使用 ask-skills 描述任务 | 给一个首选、必要依赖和用法 | 明确区分已收录、外部依赖与候选，说明审阅状态及已知问题，缺输入只问影响选择的信息 |
| 建立个人源集合 | 预览安装 | 展示计划，不创建目录 | 检测同名及已登记旧名（含 writing-master），整批阻断，不覆盖原安装 |
| 已完成无冲突安装 | 重复安装 | 已指向相同源码的链接保持不变 | 来源不同的链接报冲突 |
| 整理文件之前 | 要求找重复 | 真实识别重复组，用户文件保持原样 | 内部 _catalog 不计入内容；移动另按具体方案执行 |
| 普通文章摘要 | 只要求解释和翻译 | 在会话交付并引用真实内容 | 拿不到正文时明确报告；不默认保存笔记 |
| 每日简报规划 | 迁移 brief 资料并盘点候选任务 | 方法与来源保存到独立本地项目 | 候选清单不当作调度；当前不抓取来源 |
| 明确选择 teach | 用户指定当前系统学习任务 | 材料阅读、翻译、问答和记录都由 teach 负责 | 不另起 read；结束或切换任务按新要求处理 |
| teach 生成课程 | 已有学习目标、可信资源、记录与共享样式，要求下一节 HTML 课 | 生成目标明确的短课程，复用组件、引用主要资料并链接参考文档 | 工作区是调用时的当前目录；格式模板来自技能目录 |
| teach 检验记忆 | 要求检验延迟后的概念提取 | 练习有适当难度和即时反馈，支持间隔复习 | 测验选项不通过长度、格式或位置暗示正确答案 |
| teach 调整目标 | 教师认为当前目标需要变化，用户尚未确认 | 先提出建议，确认后更新目标并记录原因 | 保留已有目标直到用户确认 |
| 普通阅读深入追问 | 没有选择 teach，连续追问材料 | read 沿用上下文解释，不自动开课程 | 局部材料说明覆盖范围，不要求全文后才能答问题 |
| 保存阅读结论 | 明确指定知识库与保存意图 | 写入与当前意图匹配的队列或笔记 | 缺少保存位置先澄清；追问过程不逐轮创建笔记 |
| 提到待办或承诺 | 要求提醒或检查未完事项 | 基于已知事实简短提醒，按用户确认跟进状态 | 想法不自动成为承诺；旧记录先核实；不要求固定目录或生成周／日计划 |
| 已完成、取消或暂停 | 告知事项的新状态 | 停止对应催促，保留暂停或延后的约定 | 不把提醒当成完成；未答复不视为同意；无定时工具不声称已设置未来提醒 |
| 获得金融数据 | 指定来源、代码和时期 | 保留代码、日期与来源口径 | 空值、漏代码和显式服务器失败不伪装为成功 |
| 收录成熟能力 | 认可已有成熟技能并纳入集合 | 直接按用途归入正式目录，保留现有调用方式 | 新引入时间不作为试用理由；实际验证范围单独记录 |
| 保留已知问题 | 审查发现具体未解决问题 | 按用途归类，使用页和审查记录保留问题 | 不新建试用目录；目录位置不代替用户审阅或行为验证 |
| 移动已获准手动技能 | 将用户确认纳入的 teach 移入用途目录 | 安装使用新目录，手动调用设置保持原样 | 既有同名安装仍先检查来源与冲突 |
| 分批推进审查 | 原有技能尚未审完 | 第一轮只列原有待审，Matt 作为第二批引入候选，体系新增项另列 | wait-what 归原有集合，teach 已确认引入，不重复计数 |
| 新建路由或体系维护技能 | 未获用户明确批准就准备纳入集合 | 留在候选审查文档，源码和发布准入检查阻断 | 不能以自建、维护角色或 release: false 绕过确认；ask-skills 本次已获明确批准 |
| 新增第三方候选 | 上游有成熟方法，但用户尚未逐项审阅确认 | 在上游候选文档记录链接与建议，等待用户确认纳入 | 候选不进入当前技能目录、推荐、安装或发布清单 |
| 审阅已有文章 | 指定 writing-styles 并只要求审稿 | 在会话定位问题并给建议，保留原文件 | 明确要求改写时交付修订稿，明确指定文件编辑时才修改该文件 |
| 非投资分析 | 给产品材料并指定 research-analysis | 按材料给结论，保留证据缺口和来源 | 不强套公司质量、估值或股价要求；证据不足不强排次序 |
| 检查指定测试网页 | 使用 agent-browser 填入样例并确认结果 | 使用本次任务自己的会话，操作后重新观察页面状态 | 按授权范围操作，只关闭本次会话；已有 profile 问题如实说明 |
| 从动态页面提取数据 | 使用 agent-browser 整理已显示列表并附来源 | 返回实际可见的数据及覆盖范围 | 登录或访问受限时报告缺口，不把局部数据称为完整集合 |
| 寻找当前目录之外的新能力 | 使用 find-skills 查找知识库维护方法，暂不安装 | 返回外部候选、来源及与已有能力的比较 | 找到不等于纳入；内容审阅与用户确认后再决定，find-skills 已确认保留，搜索结果仍需逐项确认 |
| 多来源调查问题 | 要求比较两条技术路线，先在对话说明结论与证据 | 围绕问题查找原始资料，区分证据、推断与缺口 | 不自动生成报告目录或固定格式文件；deep-research 已获批准并完成仓库重写 |
| 核验证据支持 | 断言与材料存在否定语义或中文内容 | 回到原文判断是否真的支持该断言 | 词面评分和链接可用均不代替内容核验，实际误判记录见 deep-research 审阅 |
| 保存研究记录 | 已明确保存位置，登记来源和原文摘录 | 记录身份、位置和关联，保留原文及已有记录 | 结构检查不判断真假，不输出语义评分；损坏记录或缺失来源时停止写入 |
| 保留已有设计规则 | 仅审阅 ui-ux-pro-max 及保存行为 | 在隔离副本核对，不写用户项目 | 仓库适配已确认：过滤异常记录并报告范围，保存默认预览且不覆盖已有文件 |
| 本地评测进程失败 | 审阅 skill-creator 错误处理 | 区分执行失败与正常未触发，不宣称有效通过 | 创建与评测统一留在 skill-creator；离线测试验证故障与超时使结果不完整，不计作有效未触发 |

| 维护技能及验证结果 | 用 skill-creator 创建或修改一个技能 | 同一入口完成编写、配套资料及按需验证 | 保留原用途与调用方式；小修改不自动启动整套模型评测或替换安装 |

| 明确确认第二批写作技能 | 批准先前已比较的四项 Matt 写作技能 | 记录真实确认后纳入固定已读版本，保留原文、许可与调用方式 | 用户批准不扩大到其他候选，本机安装仍待统一处理 |
| 选择写作阶段 | 当前只要素材探索或逐步成文 | 根据用户要求推荐 fragments、shape 或 beats，文风继续独立选择 | 不将素材、两套共写循环与个人文风强制串联 |

入口里的 evals 是行为用例，不代表已经执行。本轮安装与文件检查由 smoke_test 执行；brief 的当前会话手工试用见 [验证记录](verification.md)。独立模型评测、自动选择及真实登录抓取及 writing-styles 文风效果仍未在本轮验证。
