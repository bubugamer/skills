## 创建背景与来源

核实 2026-07-22 的原始用户消息：用户在已有 tdx-api、希望寻找免费同花顺接口之后，提出「好的，AKShare你能不能也整理成 skill呢，会不会功能太多？」随后同一会话中由 Codex 新建本地 akshare-api 入口与配套工具。此前讨论过 Kimi 概念股及市场表现，这解释了概念与行情命令的设计背景；不将创建前的研究任务记作该技能的使用次数。

因此应分开两层来源：AKShare 是 akfamily 维护的第三方开源财经数据接口库；本仓库 skill 与命令封装由用户提出、Codex 编写。它不来自 Matt 的技能集合。本轮核实了创建需求和操作，未统计全量历史调用次数。

主要外部参考：[AKShare 官方文档](https://akshare.akfamily.xyz/)、[AKShare 源码仓库](https://github.com/akfamily/akshare)。本项目只维护调用方式与必要的本地封装，不把第三方库当成自己的作品。

## 当前定位和功能

它负责获取数据，为后续研究或文章提供材料。AKShare 是访问层，实际数据可能来自同花顺、东方财富、新浪或其他公开来源；每次回答应明确所选来源、日期和口径。

现有九类常用任务命令：行情快照、历史价格、概念板块、概念概况、概念历史、概念成分、公司业务、财务指标和公告。另有 search／describe／call 三个通用操作，按需要查找函数、核对参数和调用。基金、宏观等更广覆盖通过通用操作实现，不代表每类都有独立便捷命令，也不代表每个数据源已经验证可用。

这种「少量常用任务＋按需发现函数」值得保留，直接回答了用户最初对功能过多的担心：无需将整个函数目录放入 SKILL.md。

## 与 tdx-api 的关系

两者在沪深行情和历史价格上确实重合，当前使用页写「无直接同类」不准确。tdx-api 偏向通达信的行情与逐笔等数据；akshare-api 通过多个来源补充财务、公告、概念和更广数据目录。

用户现已明确确认两个入口分别保留。AKShare 覆盖多个来源，通达信另设独立入口；继续明确用户指定来源和失败后的替代策略。本次不更名、不合并。

## 实际验证与发现

在技能源码之外的临时 Python 3.11 环境安装固定依赖，未运行会往源码写 .venv 的正式启动入口。已有十项测试全部通过。帮助页、函数检索和函数说明均运行成功，检索可返回 ETF 相关函数，函数说明能显示实际签名。这些操作没有请求真实证券行情。

另用实际参数解析函数与临时复制的原启动脚本检查两个边界：

1. **通用参数会误判数字形式的字符串。** 文档示例 start_date=20260101 得到整数，而固定版本的 stock_board_industry_index_ths 签名要求字符串，并实际使用 start_date[:4]。symbol=600000 也变成整数，symbol=002432 却保留字符串。显式写成 start_date="20260101" 时可保留字符串。这是通用 call 的边界，常用 history 命令的日期路径不同，不能说全部查询都会出错。
2. **首次安装失败后的恢复不完整。** 在完全隔离的脚本夹具中模拟依赖安装失败：第一次建立了可执行 Python，但安装失败；第二次因 Python 已存在而跳过安装，直接启动并报缺依赖。两次运行只尝试安装一次。实际临时测试环境的依赖安装成功；失败是受控模拟，不是线上环境的故障判断。
3. **运行环境写入技能目录。** 现有脚本把 .venv 放在技能根下，这是代码已核实的行为。对于仓库统一安装、共享或只读来源，可能不适合；真实只读安装场景尚未测试。建议把环境放在源码之外，并按依赖版本识别是否准备完成。

本轮未查实时价格、财务或公告，未评估所有上游接口的可用性，也未验证长期数据质量。
