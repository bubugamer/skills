# ui-ux-pro-max 第一轮审阅

日期：2026-10-20。状态：用户已确认保留与整改，仓库适配入口及配套工具已完成。以下初审发现保留为依据，最终实施见文末。本机安装、外部资料和用户项目保持。

## 来源与现有组成

来源是 [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)，属于第三方 UI/UX 资料和搜索工具，不是 OpenAI 官方技能。初审时仓库仅有外部登记；用户确认后新增个人规则与 Codex 适配源码，外部资料及检索引擎仍不复制。

本机 SKILL.md 指纹 eb540d8262789975a8c1b7403b598bbd4f9d775642e9a91c4d5beabe93d0a98f，与最初 catalog 一致。目录包含入口、30 个 CSV 资料文件和三个搜索／方案生成脚本。本轮读取的上游当前入口和 search.py 均与本机不同；当前上游入口没有本地 User Preference Overrides 段落。这说明需要区分个人增量与第三方版本，不能直接升级覆盖，但这不是完整历史版本差异审计。

本机包含三类内容：

1. 通用资料：视觉风格、配色、字体、图表、交互指南和平台资料。
2. 个人方法：克制浅色、内容优先、一个页面一个主要任务、同级视图用 tabs、动作靠近结果、状态只表达影响下一步的信息等。
3. 具体操作：搜索、生成设计方案、保存主规则及页面覆盖规则。

个人规则是在使用中形成的有效积累，应继续属于 skill，可拆到配套参考；不因规则属于个人偏好就迁去某个项目或丢弃。某个项目已有设计系统或用户明确要求其他方向时，按当次要求选择。

## 实际使用场景

| 场景 | 用户可以怎样提出要求 | 使用内容 | AI 如何协助 | 最终产出 |
| --- | --- | --- | --- | --- |
| 新产品页面缺少视觉方向 | 给这个咖啡工具找合适的配色、字体和布局方向 | 通用资料检索与个人偏好 | 提供少量合适选项并解释任务适配性 | 可选择的视觉与布局方案 |
| 检查页信息组织混乱 | 看看这个数据检查页该如何组织，沿用我的习惯 | 个人工具页与工作流规则 | 先梳理页面任务、信息层级、动作与结果，再调整表达 | 具体的页面结构与交互建议 |
| 局部交互需要改进 | 检查键盘焦点和错误提示，保留现有视觉系统 | UX 条目与真实页面 | 查相关原则，再对照实际界面和实现 | 问题位置、原因与修改建议 |
| 实现特定平台组件 | 这是 React 网页，不是移动应用，给出对应实现建议 | 实际栈资料与项目代码 | 按真实平台选择适用建议 | 符合当前平台的实现方向 |
| 希望保存经过确认的设计规则 | 把已确认的规则保存，保留我以前改过的内容 | 有边界的保存与合并流程 | 先比较已有规则与新建议，再按范围更新 | 保留既有决定的设计文档 |

搜索工具提供资料和候选，不直接证明设计适合页面。实际可用性、响应式、键盘访问与页面视觉需要在页面上检查；本轮没有建立或验收真实页面。

## 发现的问题

- 入口 description 只有一句泛泛介绍，不能清楚说明什么时候选它。文档重复出现设计系统步骤，并要求始终先生成完整方案；不适用于局部问题或已有设计系统的任务。
- 一处要求按项目判断平台，另一处又要求始终加 react-native。当前脚本实际只接受这一栈，尽管资料目录包含其他栈文件。
- 多次引用 Quick Reference §1–§9，但当前入口没有对应的编号参考章节；指令存在失效引用。
- 设计系统生成仍可能给工具检查页套用营销页面模式；输出需要按页面任务审查，不能原样视为已确认设计系统。
- 本轮输出混入原始 CSV 后续行；landing.csv 的第 27 条解析记录吞入后续行片段，styles.csv 另有字段错位记录。不是命令返回成功就说明资料解析正确。
- 文档多处写 design-system/MASTER.md，实际生成路径含项目名；生成后的主规则又指向不含项目名的页面位置。
- 保存使用写入模式直接重写已有主规则和页面文件，实测会覆盖人工修改。使用 --persist 之前必须解决或绕开这一行为，不能将其当作保留已有规则的更新器。
