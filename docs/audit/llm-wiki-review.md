## 当前设计问题

1. **个人工作区与通用能力耦合。** 即使公开版把绝对根路径换成占位符，仍固定 02-Areas、03-Resources、特定共读笔记位置、MkDocs、端口和虚拟环境。目录与页面规范应由知识库项目提供。
2. **入口职责扩张且篇幅较长。** 主文约 384 行，混入完整模板、证据格式、具体产品出题样例、站点启动和重复的交接规则。核心工作流与模板、站点适配可以分开。
3. **说明与脚本落后于当前导航。** 主文采用 topic 总览、精简首页和完整 MkDocs 导航，脚本仍按旧全页索引生成；参考文档还使用 _wiki-index.md、_index-* 等另一套命名。
4. **查询与写回约定不一致。** 纯 Query 段说发现问题只建议；对谈式 Query 段又要求讨论收束就写回。应依据用户本次要求及已有保存授权决定，而不是由讨论结束推断授权。
5. **模板与站点约定不一致。** 主文要求 visibility，但配套六种模板都未提供该字段。当前个人站点确有项目自己的 filter_private.py 和 CI 调用；过滤是项目实现，不能视为通用 skill 自带保证。本次未运行发布、过滤脚本或真实站点构建。
6. **遗留分类文案。** 末尾仍称 trial，与用户取消试用目录的决定不一致；本轮仅清除此称谓，保留手动调用方式和索引写入限制。

## 实际脚本验证

全部脚本运行使用自动清理的临时知识库，不修改真实 Wiki。基本输入包含 index.md、topic.md、guide.md、log.md 和父目录 mkdocs.yml。

| 输入与操作 | 实际结果 | 结论 |
| --- | --- | --- |
| guide.md 正文含目标为 missing.md 的普通 Markdown 链接，运行 lint --json | broken_links 为空。 | 普通 Markdown 断链漏报。 |
| 同一位置改为双中括号 missing-wiki，运行 lint --json | 正确报告 guide.md 的 missing-wiki。 | 双中括号断链检测基本有效，不能把所有链接检查都说成不可用。 |
| guide.md 的来源采用 YAML 多行列表 sources 加 source.md | guide.md 仍出现在 missing_sources 中；index 和 log 也被当作缺来源知识页。 | 自制属性解析器不支持常见多行 YAML，页面角色也未正确区分。 |
| 精简首页只列 Topic；topic 页列 Guide，运行 rebuild_index --dry-run | 输出同时列 index.md、log.md 和 Guide。 | 把首页与日志当作内容，违背精简首页约定。 |
| 在同一临时目录运行索引写入模式 | 原首页被全页列表替换，出现首页自链接；mkdocs.yml 内容不变。 | 索引重建没有执行当前宣称的导航维护流程。 |
| 对 lint 传 --dry-run | 返回码 2，提示不支持该参数。 | 主文命令说明错误；lint 本来就是只读。 |
| 对空目录运行 lint --json | 返回码 0，输出普通文本 No wiki pages found. | 机器读取模式不总是返回 JSON。 |
| 对 lint 前后所有临时文件计算内容摘要 | 摘要一致。 | 当前 lint 的检查过程是只读的，尽管报告有漏报和误报。 |

## 建议的整改方向

建议保留为长期知识库编辑与检索入口，主流程收敛为编入、查询、维护。是否保留知识库自测，由用户确认其实际价值；完整课程仍按用户明确选择使用 teach。

SKILL.md 只保留用途、先查已有页面、按证据更新、维护关联和按授权写入。页面模板、证据格式、导航算法放配套参考；根目录、来源位置、页面属性、索引与站点命令放各知识库的项目配置，避免全局固定个人路径。站点启动作为已配置项目的可选操作。

修复脚本前，索引写入限制继续保留。建议让索引与链接检查读取同一套项目约定；测试须覆盖精简首页、topic、完整导航、普通 Markdown 与双中括号链接、多行来源和维护页角色。

命名可考虑 wiki，以直接表达知识库用途；本轮尚未改名。也未修改提醒、阅读、教学或目录整理能力的功能，未启用默认发布或改写本机 llm-wiki 安装。
