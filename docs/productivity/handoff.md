# handoff

把当前会话整理成交接文档供下一位 agent 接手。状态：已收录，列入默认发布清单。

## 为什么保留或调整

用户需要把会话中的工作移交给下一会话或 agent。保留上游短交接方法及 MIT，按 Codex 映射调用设置并使用中文回复。详见 [纳入记录](../audit/handoff-adoption.md)。

用户明确批准接入并安装。沿用上游手动调用。


## 使用场景

| 具体场景 | 你可以怎样提出要求 | 用哪个 skill | AI 会怎样协助 | 最终产出 |
| --- | --- | --- | --- | --- |
| 把当前会话移交给已有会话或另一个 agent | `$handoff` 为下一位 agent 写交接稿，记录已完成事项、关键决定和接手第一步。 | `$handoff` | 提炼相关会话内容，引用已有计划、提交和文件，省略敏感信息。 | 一份可由接手方读取的交接文档。 |
| 长任务分段，下一会话要专注回归验证 | `$handoff` 将当前工作整理成交接稿，下一会话重点检查尚未覆盖的回归场景。 | `$handoff` | 按指定接手重点筛选进展、验证证据和未解决的问题，给出下一步。 | 围绕验证任务的短交接稿及证据引用。 |

## 输入与依赖

在源会话中手动选用，提供接手重点。接收方需要能读取交接稿和引用的资料，跨机器时需提供对应内容。依赖：以操作入口的当前工具检查为准。已有授权继续适用；缺少事实先检查，缺少用户决定再询问。

## 怎样算完成

在系统临时目录交付交接稿。写清接手目标、进展和下一步，引用已有资料并省略敏感信息。

## 与相邻能力的关系

对照：Codex Fork（从原会话历史创建新会话）；handoff（生成可交给已有会话或其他 agent 的交接文档）。按本次目的选择；名称相似不代表输出相同。
